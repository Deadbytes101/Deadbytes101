# DEADBYTE

I like old PCs, C, assembly, and finding out what the machine is actually doing.

I end up writing things that already exist: compilers, boot code, file formats, Win32 tools, sometimes a motherboard. I learn more that way. A hex dump tells me more than a pretty screenshot.

Terry A. Davis is my idol. I like that he built his own tools and understood the machine underneath them.

**MOST PEOPLE WRITE CODE TO SOLVE PROBLEMS.**  
**I WRITE CODE BECAUSE I DO NOT WANT TO DEPEND ON ANYONE ELSE'S SOFTWARE.**

## Languages, kernels, strange machines

- [DBYTE](https://github.com/Deadbytes101/DBYTE) — My language. Compiler, VM, and the beginnings of an OS.
- [BONEBOX-01](https://github.com/Deadbytes101/BONEBOX-01) — Real-mode x86, from boot sector to shell.
- [LOOM](https://github.com/Deadbytes101/LOOM) — An x86-64 OS experiment with cells instead of a resident kernel.
- [SHINESEA](https://github.com/Deadbytes101/SHINESEA) — Filesystem images, extents and recovery tests.
- [CINDER-16](https://github.com/Deadbytes101/CINDER-16) — A 16-bit machine written in Io. The debugger runs backwards, too.
- [DBLYATEM](https://github.com/Deadbytes101/DBLYATEM) — Parsing and checking PE/AMD64 binaries.
- [DBYTE-HOLYC-OPT](https://github.com/Deadbytes101/DBYTE-HOLYC-OPT) — Working inside Terry's original HolyC optimizer. Early work.

## Stuff I can run

- [DBYTEPAD](https://github.com/Deadbytes101/DBYTEPAD) — A Win32 editor in C, including some absurdly small builds.
- [DEADFLASH](https://github.com/Deadbytes101/DEADFLASH) — Writes disk images. Reads them back. Checks.
- [DEADBYTE-RECLAIM](https://github.com/Deadbytes101/DEADBYTE-RECLAIM) — Windows uninstall and rollback tool.
- [DBNET](https://github.com/Deadbytes101/DBNET) — Network diagnostics and Windows network experiments.
- [DEADWIRE-HTTPD](https://github.com/Deadbytes101/DEADWIRE-HTTPD) — Small HTTP/1.0 server; some of it is assembly.
- [BYTE-KEEPER](https://github.com/Deadbytes101/BYTE-KEEPER) — M0TE lives here. A little byte creature in a Rust program.

## Pixels

- [DEADGL](https://github.com/Deadbytes101/DEADGL) — C99 software rasterizer. Just memory and pixels.
- [DGP-1](https://github.com/Deadbytes101/DGP-1) — Designing a fixed-function GPU: RTL, textures, scanout. Not a board yet.
- [dbyte-dbpx](https://github.com/Deadbytes101/dbyte-dbpx) — A small lossless image format of my own.

## Boards, ROMs, old iron

- [DBYTE-370](https://github.com/Deadbytes101/DBYTE-370) — Socket 370 ATX board design. Pentium III and VIA chips.
- [S3CORE01](https://github.com/Deadbytes101/S3CORE01) — SG2002 RV64 computer board. Routing is not the same as booting.
- [USBDEADFLASH](https://github.com/Deadbytes101/USBDEADFLASH) — Building a USB 3.0 flash drive from the schematic up. No finished hardware.
- [A780L3B BIOS research](https://github.com/Deadbytes101/dbyte-a780l3b-bios-research) — ROM dumps, patches and chip reads on a BIOSTAR board.

## Leftovers and side quests

- [RIGOS](https://github.com/Deadbytes101/RIGOS) — USB-bootable CPU mining appliance.
- [JOBSIM-DESKTOP](https://github.com/Deadbytes101/JOBSIM-DESKTOP) — Mouse/keyboard experiment for Job Simulator. Archived.
- [Shower Game remaster study](https://github.com/Deadbytes101/shower-game-remastered-2015) — Research and source planning, not a finished remake.

Some of these work. Some only work in QEMU. Some are still drawings in KiCad. The repo README is where I keep the actual state.
